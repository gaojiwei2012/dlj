# R003 浏览器 / API 验收清单

建议至少准备：发布者、乘客 A、乘客 B 三个普通学生账号。

- [ ] 01 发布者创建公开自驾计划，设置 3 个座位并填写联系方式。
- [ ] 02 未填写联系方式时，提供可预约座位的计划不能保存。
- [ ] 03 未预约的 A 在寻搭子列表只能看到剩余 / 总座位，看不到联系方式。
- [ ] 04 发布者本人看到自己的计划，但不能出现“预约自己的座位”操作。
- [ ] 05 A 点击“预约座位”后出现二次确认。
- [ ] 06 A 确认后无需审批即预约成功，剩余 3 → 2。
- [ ] 07 A 预约成功后能看到发布者联系方式。
- [ ] 08 B 尚未预约时仍然看不到该联系方式。
- [ ] 09 A 再次预约同一计划不会重复占位，页面显示“已预约 / 取消预约”。
- [ ] 10 A 点击取消时出现二次确认。
- [ ] 11 A 确认取消后剩余 2 → 3，联系方式从 A 页面撤回。
- [ ] 12 重复取消不会再次增加座位。
- [ ] 13 B 不能取消 A 的有效预约。
- [ ] 14 只剩最后 1 个座位时，两名用户同时预约只成功 1 人，剩余不能为负数。
- [ ] 15 剩余为 0 时计划仍展示，但明确标记“已满”，不再出现预约按钮。
- [ ] 16 有有效预约时，发布者不能取消公开或删除该计划。
- [ ] 17 有 2 个有效预约时，发布者不能把总座位数改为 1。
- [ ] 18 发布者可以在不低于有效预约人数的范围内调整总座位，剩余量同步正确。
- [ ] 19 非自驾 / 未提供座位的公开计划继续正常展示，但没有预约按钮。
- [ ] 20 手机窄屏下卡片、联系方式和预约/取消按钮无横向溢出或遮挡。
- [ ] 21 R001 合规统计、R002 预测、R004 学生总览回归无异常。
