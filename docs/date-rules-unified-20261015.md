# 2026-10-15 日期规则合并说明

## 判定次序（适用于实际逗留、学生出行预测与老师端查看）

1. 澳门公共假期：无论是否有集中课程，均不符合。
2. 无效逗留日期：无论来自原 `invalid_date_ranges` 日期区间还是 `date_rules.MANUAL_INVALID` 单日规则，均不符合；即使当天是集中课程亦不例外。
3. 普通工作日：累计逗留满四小时后完全符合，否则部分符合。
4. 周末：仅在该日期被当前学年的在用 `course_sessions` / `course_dates` 覆盖时，累计逗留满四小时后完全符合；未安排集中课程的周末，即使满四小时也只能部分符合。
5. 时间尚未知、尚在签到中的记录沿用原先的未知／进行中逻辑。

`VALID_WEEKEND` 是已弃用的历史数据库枚举，保留旧行用于数据溯源；它不再授予周末资格，也不会出现于新的日期说明或管理员设置选项。

## 后台管理方式（统一“公共假期”添加入口）

- 后台仅保留一张 **「公共假期与无效逗留日期」** 管理卡片；之前独立的「无效逗留日期」卡片移除，不再出现两个添加位置。
- 同一个表单通过「日期类型」区分：**澳门公共假期**（选择单日）与 **无效逗留日期（含强制无效）**（选择单日或连续区间）。两种类型都会被统计引擎优先排除，即使是集中课程日也无效。
- 同一个列表展示所选公历年份所有有效的公共假期、旧 `MANUAL_INVALID` 单日及 `invalid_date_ranges` 区间；修改、停用均在这张卡片操作。
- `GET /api/admin/date-rules?year=YYYY` 新增 `exceptionRecords` 字段，返回统一列表；每项包含 `source_type`（`MANUAL_RULE` 或 `RANGE`）、`type`、起止日期、原因及原始 ID。仍保留旧 `dates` 数据供展开的周末/课程明细读取。
- 旧单日按原 ID 调用日期规则 API，旧区间按原 ID 调用无效日期 API。新公共假期写入 `date_rules`，新无效逗留日期写入 `invalid_date_ranges`。无需迁移或删除旧行。
- 无效逗留日期限定在**当前启用学年**内；其他学年的无效日可在所选公历年份中查看，但不可修改。公共假期按公历年份添加。
- 「同步本年度周末」及全年日级判定仍保留在该卡片；明细默认折叠，避免干扰日期新增和维护。周末同步仅作记录，不赋予有效资格。
- 原 `GET /api/admin/config` 的 `invalidRanges` 及其历史兼容接口继续可用，保障旧客户端。

## 兼容及部署

- 不改 SQLite 表结构、不修改或删除旧记录。已有的 `VALID_WEEKEND` 记录自动失去判定效力，**历史逐日统计刷新后可能由完全符合变为部分符合**；无需单独运行迁移。
- 跨来源重复的无效日写入会被阻止（409），以避免同一日期同时拥有两条独立可编辑的无效配置。
- 部署前先备份生产 SQLite 数据库，然后在测试环境执行 `node --test`、`npm ci && npm run build`，最后替换服务器应用代码并重建容器。切勿以打包内的测试数据库或 `.env.test` 覆盖正在运行的资料。
