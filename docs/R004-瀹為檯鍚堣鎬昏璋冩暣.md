# R004 管理端统计口径调整（2026-09-30）

## 本轮产品决定

老师查看学生时聚焦**实际逗留**。老师端总览和单人详情不再呈现 R002 计划截至当前、计划预测、净差异或计划列表；学生本人的计划、预测和执行偏差功能仍然完整保留。

### 管理端三项主要统计

| 指标 | 计算口径 | 是否计入学年90天目标 |
|---|---|---|
| 完全符合 | 当前学年日级 R001 `compliantDays` | 是 |
| 部分符合 | 当前学年日级 R001 `partialDays` | 否 |
| 完全＋部分合计 | `compliantDays + partialDays`（同一学生，每类已按自然日去重） | 否，属于展示指标，**不能当作达标天数** |

合计不包括 `NON_COMPLIANT`（不符合）、`TIME_UNKNOWN`（待补正）、`IN_PROGRESS`（进行中）及 `NO_STAY`（无记录）。顶部汇总是**各学生的统计值相加**；如果两个学生在同一日都完全符合，应计为两个学生日，而不是一个唯一日历日期。

### 老师页面

- 顶部：学生总数、当前正在签到、全体学生完全符合累计、部分符合累计、两类累计、统计学年。
- 列表：学生／当前状态、完全符合（含时长）、部分符合（含时长）、两类合计、学年目标／剩余、操作。
- 筛选：姓名／账号和账号状态。移除“计划执行净差异”筛选及说明。
- 单人详情：三个主要指标、其他实际分类、目标／剩余、逐日实际合规和原始签到／签退历史；不再下发或显示计划数据。
- 日期规则管理、课程、旧的「全部人员」账号管理仍按原实现保留；切换学年和规则修改后实时查询结果。

### 代码和 API 变更

- `server/services/admin-students.mjs`：继续复用 R001 `getUserCompliance()`，不再额外调用 R002 `getUserPlanPrediction()`；列表和详情增加 `compliantAndPartialDays`，不再提供 `planPrediction`/`plans`。
- `src/components/admin/StudentOverview.vue`：按实际统计重排桌面端与窄屏布局。
- `test/r004-admin-students.test.mjs`：验证两类合计、规则变化后重新分类、剩余目标只按完全符合计算，以及学生端 R002 仍然可用。
- 不新增表、不迁移数据库，继续使用 R003 的 schema v3。

此文件是对原 `R004-phase1.md` 中“老师展示 R002”的**后续需求调整**，不应将原始阶段记录误认为此版仍需展示计划。

## 管理端比值展示补充（2026-09-30）

老师端总览、单人详情改用相同的三项「实际天数 / 学年目标天数」：

- 完全符合：`compliantDays / targetDays`；
- 部分符合：`partialDays / targetDays`（仅比较，不意味着已达到严格合规要求）；
- 累计符合（完全＋部分）：`compliantAndPartialDays / targetDays`，不含不符合、待补正、进行中、无记录。

例如 1 天完全符合、2 天部分符合、90 天目标，应分别显示 **1/90、2/90、3/90**。学年目标按当前选择动态显示，不将 90 写死。

上方全体学生汇总使用对应的分子之和和**所有学生目标之和**作为分母。例如两名学生、目标各为 90 天时，全体汇总分母为 180，不误写为 90；姓名搜索仅过滤列表，不影响全体汇总。原 R001/R002 学生端计算及 3100 测试数据库均不更改。
