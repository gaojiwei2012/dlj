# R003 自驾寻搭子座位预约与取消 — Phase 1

日期：2026-09-30

## 已实现

- 公开、有效、未过期的自驾计划可提供 1–6 个可预约座位。
- 发布者在提供座位时必须填写联系方式类型（微信 / 手机号 / 其他）及联系方式。
- 未预约的普通浏览者不会从 `/api/companions` 获得联系方式字段；发布者本人及当前有效预约用户可以获得。
- 其他登录用户可确认预约 1 个座位，无需发布者审批；成功后立即扣减剩余座位并显示联系方式。
- 同一用户对同一计划同一时刻仅允许一个 `RESERVED` 预约；取消后可再次预约。
- 预约用户可以二次确认取消；取消后状态改为 `CANCELLED`、座位返还，接口不再下发联系方式。
- 发布者本人不能预约自己的座位；座位为 0 时返回已满；最后一个座位的扣减与预约写入在 `BEGIN IMMEDIATE` 事务内完成。
- 有有效预约时，禁止发布者静默取消公开、关闭座位、删除计划，或把座位总量改到低于有效预约人数。
- “我的出行计划”显示座位总量、剩余座位、有效预约人数；“寻搭子”显示预约 / 已预约 / 取消预约 / 已满状态。
- 移动端将寻搭子卡片操作区改为纵向全宽按钮。

## 数据结构

Schema 升级到 v3：

- `travel_plans` 增加 `contact_type`、`contact_value`、`seat_capacity`。
- 新增 `travel_seat_reservations`，状态为 `RESERVED / CANCELLED`。
- 原有自驾计划升级时以旧 `seat_count` 回填 `seat_capacity`，不删除旧计划。
- `seat_count` 在 v3 中表示当前剩余可预约座位；`seat_capacity` 表示发布者设置的座位总量。

## API

- `POST /api/travel-plans/:id/reservations`：预约当前计划的 1 个座位。
- `DELETE /api/travel-plans/:id/reservations/me`：取消当前用户自己的有效预约。
- `GET /api/companions`：增加剩余 / 总座位、本人预约状态、是否已满、是否可预约；联系方式按权限条件返回。
- 原 `GET/POST/PATCH/DELETE /api/travel-plans*` 保留，并增加座位容量、联系方式和有效预约保护。
